    User Guide

    Model Loading & Saving

    CoMLRL supports both homogeneous and heterogeneous models from Hugging Face or local directories. Users can specify Hugging Face model identifiers through agent_model/critic_model for homogeneous setups, or provide agents/critics lists for heterogeneous setups. Trained agents can be saved and loaded into a new trainer for further training.

    Loading LLM Agents#

    Homogeneous Agents#

    Users can initialize homogeneous agents by setting agent_model to a single model identifier and leaving agents=None. For trainers with a separate num_agents constructor argument, users can set it alongside the matching configuration value; the configuration alone does not override it.

    The following example loads 3x Qwen/Qwen2.5-1.5B agents:

    trainer = MAGRPOTrainer(
    agent_model="Qwen/Qwen2.5-1.5B",
    agents=None,
    num_agents=3,
    reward_func=reward_func,
    train_dataset=train_dataset,
    args=MAGRPOConfig(num_agents=3, num_turns=1, temperature=0.7, top_p=0.9, top_k=None),
)

    Heterogeneous Agents#

    Although homogeneous agents can be prompted to take on different roles and work on separate parts of a task in parallel, heterogeneous agents can also contribute the specialized capabilities of different models.

    Users can initialize heterogeneous agents by supplying model identifiers or loaded model objects in agents, with compatible tokenizers supplied through tokenizer. With agents supplied, agent_model can remain None. If both are provided, their model names must match, and their list lengths must match the number of agents; otherwise, training raises an error.

    The following example loads Qwen/Qwen2.5-Coder-3B + Qwen/Qwen2.5-Coder-7B agents:

    trainer = MAGRPOTrainer(
    agent_model=None,
    agents=["Qwen/Qwen2.5-Coder-3B", "Qwen/Qwen2.5-Coder-7B"],
    reward_func=reward_func,
    train_dataset=train_dataset,
    args=MAGRPOConfig(num_agents=2, num_turns=1, temperature=0.7, top_p=0.9, top_k=None),
)

    Loading LLM Critics#

    Algorithms such as Independent Actor-Critic (IAC) and Multi-Agent Actor-Critic (MAAC) use LLM critics. How these critics are loaded depends on the algorithm and the use_separate_critic setting.

    Centralized Critic#

    Users can load a separate centralized critic through critic_model or a one-element critics list. It must be a supported causal language model: the trainer adds a value head and encodes the joint input with the first actor’s tokenizer, so that tokenizer must also be compatible with the critic.

    The following example pairs Qwen/Qwen2.5-Coder-3B + Qwen/Qwen2.5-Coder-1.5B actors with a centralized Qwen/Qwen2.5-Coder-7B critic:

    trainer = MAACTrainer(
    agent_model=None,
    agents=["Qwen/Qwen2.5-Coder-3B", "Qwen/Qwen2.5-Coder-1.5B"],
    tokenizer=[
        AutoTokenizer.from_pretrained("Qwen/Qwen2.5-Coder-3B"),
        AutoTokenizer.from_pretrained("Qwen/Qwen2.5-Coder-1.5B"),
    ],
    critic_model="Qwen/Qwen2.5-Coder-7B",
    critics=None,
    reward_func=reward_func,
    train_dataset=train_dataset,
    args=MAACConfig(num_agents=2, num_turns=1, temperature=0.7, top_p=0.9, top_k=None),
)

    Independent Critics#

    With independent critics, each agent can have its own critic. With use_separate_critic=True, users can supply one critic_model identifier to load a separate copy per agent, or a critics list of length num_agents. Each separate critic receives token IDs from its actor’s tokenizer and must be compatible with it. With use_separate_critic=false, each actor and critic share an LLM backbone and load together. In this case, critic_model and critics remain unset (null or None). As with agents, supplying both critic_model and critics requires matching model names and lengths; otherwise, training raises an error.

    The following example loads Qwen/Qwen2.5-Coder-3B + Qwen/Qwen2.5-Coder-7B actors with separate critics based on the same models:

    trainer = IACTrainer(
    agent_model=None,
    agents=["Qwen/Qwen2.5-Coder-3B", "Qwen/Qwen2.5-Coder-7B"],
    tokenizer=[
        AutoTokenizer.from_pretrained("Qwen/Qwen2.5-Coder-3B"),
        AutoTokenizer.from_pretrained("Qwen/Qwen2.5-Coder-7B"),
    ],
    critic_model=None,
    critics=["Qwen/Qwen2.5-Coder-3B", "Qwen/Qwen2.5-Coder-7B"],
    reward_func=reward_func,
    train_dataset=train_dataset,
    args=IACConfig(
        num_agents=2,
        num_turns=1,
        use_separate_critic=True,
        temperature=0.7,
        top_p=0.9,
        top_k=None,
    ),
)

    Alternatively, each actor can share the same model with its critic:

    trainer = IACTrainer(
    agent_model=None,
    agents=["Qwen/Qwen2.5-Coder-3B", "Qwen/Qwen2.5-Coder-7B"],
    tokenizer=[
        AutoTokenizer.from_pretrained("Qwen/Qwen2.5-Coder-3B"),
        AutoTokenizer.from_pretrained("Qwen/Qwen2.5-Coder-7B"),
    ],
    critic_model=None,
    critics=None,
    reward_func=reward_func,
    train_dataset=train_dataset,
    args=IACConfig(
        num_agents=2,
        num_turns=1,
        use_separate_critic=False,
        temperature=0.7,
        top_p=0.9,
        top_k=None,
    ),
)

    Trainers use agents/critics lists internally. The agent_model and critic_model parameters are shortcuts for homogeneous setups and must be consistent with any corresponding lists supplied.

    MAGRPO loads tokenizers automatically for model identifier strings. MAAC/IAC load a tokenizer automatically for agent_model, but require an explicit tokenizer when agents is supplied, even if it contains strings. Loaded model objects require one compatible shared tokenizer or a tokenizer list matching the actors. Heterogeneous actors may have different vocabularies when each uses its own compatible tokenizer; separate critics must also accept their actor’s token IDs (the first actor’s IDs for MAAC).

    Saving & Resuming Training#

    Saving Models#

    Users can call save_model(output_dir) after training to explicitly save the actors’ Hugging Face model configurations, weights, and tokenizers to local directories:

    trainer.train()
trainer.save_model("./saved-models/run-1")

    Training from Saved Models#

    Users can continue training a saved two-actor MAGRPO setup by supplying the actors’ directories in the original role order. The parent run-1 directory contains the actors; each agent_i directory is a loadable model.

    from comlrl.trainers.reinforce import MAGRPOConfig, MAGRPOTrainer

continued_trainer = MAGRPOTrainer(
    agents=[
        "./saved-models/run-1/agent_0",
        "./saved-models/run-1/agent_1",
    ],
    num_agents=2,
    reward_func=reward_func,
    train_dataset=train_dataset,
    args=MAGRPOConfig(
        num_agents=2,
        num_turns=1,
        num_train_epochs=3,
        agent_learning_rate=5e-6,
        temperature=0.7,
        top_p=0.9,
        top_k=None,
    ),
)
continued_trainer.train()
continued_trainer.save_model("./saved-models/run-2")

    MAGRPO loads tokenizers from the actor directories automatically. Here, num_train_epochs=3 means three epochs in the new training run. The dataset, reward function, training configuration, and any custom formatters, reward processor, or external transition must be supplied again; save_model does not store them.

    Other trainers support the same local-directory approach, subject to the tokenizer and actor-count requirements above. Preference trainers start preference collection and reward learning according to the new run’s configuration.

    Restoring Value Heads#

    This section applies to save_model exports. Training checkpoints restore value heads automatically.

    IAC and MAAC save value heads separately as value_head.pt. Loading a critic or shared actor directory through the constructor restores the language-model backbone and creates a new value head. Users can retain the learned values by explicitly restoring the saved head before calling train().

    For a saved two-actor MAAC setup using the default linear value head:

    from pathlib import Path
import torch
from transformers import AutoTokenizer
from comlrl.trainers.actor_critic import MAACConfig, MAACTrainer

saved_dir = Path("./saved-models/maac-run-1")
actor_dirs = [str(saved_dir / f"agent_{i}") for i in range(2)]

continued_maac = MAACTrainer(
    agents=actor_dirs,
    tokenizer=[AutoTokenizer.from_pretrained(path) for path in actor_dirs],
    critic_model=str(saved_dir / "critic"),
    reward_func=reward_func,
    train_dataset=train_dataset,
    args=MAACConfig(num_agents=2, num_turns=1, num_train_epochs=3),
)
continued_maac.critics[0].value_head.load_state_dict(
    torch.load(
        saved_dir / "critic" / "value_head.pt",
        map_location="cpu",
        weights_only=True,
    )
)
continued_maac.train()
continued_maac.save_model("./saved-models/maac-run-2")

    For IAC, the same load_state_dict step applies to continued_iac.agents[i].value_head when use_separate_critic=False, or to continued_iac.critics[i].value_head when it is True. Separate critic backbones also require loading through critic_model or critics.

    The value-head architecture must match the saved run. IAC requires the original IACConfig.value_head_hidden_dim for shared heads and IACConfig.critic_value_head_hidden_dim for separate heads. A custom MAAC head requires the original model_config={"critic_value_head_hidden_dim": ...} in the trainer constructor. Continuing the same value-learning setup also requires the original critic_type ("v" or "q").

    Training State#

    Users can enable training checkpoints through train(checkpoint_dir=...) and resume a compatible trainer with resume_from_checkpoint:

    # Save a checkpoint at each completed training boundary.
trainer.train(checkpoint_dir="./checkpoints", checkpoint_interval=1)

# Recreate the trainer with the same models, tokenizers, data, and callbacks.
resumed_trainer.train(
    resume_from_checkpoint="./checkpoints/checkpoint-1",
    checkpoint_dir="./checkpoints",
    checkpoint_interval=1,
)

    Checkpoints preserve model and optimizer states, training progress, and random states, along with preference-learning data and history where applicable.

    Checkpoints are saved at completed epochs, iterations, or preference-learning stages, with a final save at completion. checkpoint_interval controls periodic saves. Resuming repeats any work since the last checkpoint.

    num_train_epochs and num_iterations count the total run, including completed work, and can be increased when resuming. Models, tokenizers, data, and training settings must remain compatible. Stateful datasets and callbacks can provide state_dict() and load_state_dict(); external service state is not restored.

    If a preference-learning output directory already contains files, resumed output goes into a resume-* subdirectory.

    For W&B, users can merge the saved run identity into their existing wandb_config before constructing the trainer. This preserves logging and output settings and avoids opening an empty run during construction:

    from comlrl.utils import read_checkpoint_metadata

checkpoint = "./checkpoints/checkpoint-1"
identity = read_checkpoint_metadata(checkpoint)["wandb"]
if identity and "id" not in wandb_config and "resume" not in wandb_config:
    wandb_config = {**wandb_config, **identity, "resume": "allow"}

# Pass wandb_config to the trainer constructor before resuming.

    Explicit id or resume settings take precedence. If the checkpoint contains no W&B identity, the helper returns None for wandb and the existing configuration is kept.

    Checkpointing is disabled by default: train() without checkpoint options saves no training checkpoints. save_model() exports models only; it does not save the full state needed to resume training.
