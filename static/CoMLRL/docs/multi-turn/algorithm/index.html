    Multi-Turn Interaction

    Multi-Turn Algorithm

    Many complex problems require more than one turn to solve. LLM agents interact with the environment to obtain useful feedback from other models or tools in the system.

    Multi-Turn MAGRPO#

    Multi-turn MAGRPO builds a rollout tree whose branches represent different joint responses (TreeRPO).

    Each episode begins with a task sampled from the dataset, which provides the initial observations \( \mathbf{o}_0=\{o_{1, 0}, \cdots, o_{n, 0}\} \) and histories \( \mathbf{h}_0=\{h_{1, 0}, \cdots, h_{n, 0}\} \) for all agents. At each turn, agents generate a group of joint responses \( \mathbf{a}^{\mathcal{G}}_t\gets\boldsymbol{\pi}^{\mathcal{G}}(\cdot|\mathbf{h}_t) \) from their current observation-action history \( \mathbf{h}_t \). Each response starts a distinct rollout. Agents receive joint rewards \( r^{(g)}_{t} \) for each response, based on the accumulated history and current joint action \( \mathbf{a}^{(g)}_{t} \in \mathbf{a}^{\mathcal{G}}_{t} \). Each rollout then evolves independently, producing new joint observations \( \mathbf{o}^{\mathcal{G}}_{t+1} \) as the environment evolves and branching into further rollouts at the next turn \( t+1 \). This process continues until the terminal turn \( H \).

    Joint Mode#

    MAGRPO supports two modes for forming joint responses at each turn:

    • Aligned (joint_mode="aligned"): Responses with the same generation index are combined across agents. Each agent samples \( G \) responses (the fixed num_generations value) at every node. With \( T \) turns and no early termination, the tree has \( G^T \) leaves.
    • Cross (joint_mode="cross"): The Cartesian product of the agents’ sampled responses yields \( G^N \) joint actions per node. With no early termination, the tree has \( G^{N \cdot T} \) leaves. Responses are reused across combinations, so the joint samples are not independent. This increases the number of reward evaluations and the rollout size without guaranteeing more accurate value estimates.

    Only responses from the same rollout can be combined because rollouts evolve independently. The current MAGRPO implementation accumulates undiscounted returns: discount does not change its tree recursion. MAREINFORCE describes return aggregation and advantage normalization.

    Multi-Turn MAAC/IAC#

    The MAGRPO rollout tree generates numerous samples per episode. In the multi-turn setting, MAAC/IAC generate only one sample per agent per turn, and the episode continues across turns until termination. MAAC/IAC use one-step temporal-difference targets, with discount applied to the next rollout value and no bootstrapping after the final or early-terminated turn. The current implementation collects the full episode before buffering its samples. Policy updates occur when rollout_buffer_size is reached, and any remaining buffer is flushed at the end of the epoch. Policies are not updated between turns of the same episode. External feedback controls how environment observations are incorporated into prompts for subsequent turns. This mechanism is usually implemented in CoMLRL’s downstream environments.
