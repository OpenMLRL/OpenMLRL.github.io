    Overview

    Welcome to CoMLRL's documentation  👋

    Cooperative Multi-LLM Reinforcement Learning (CoMLRL) is an open-source library for training multiple LLMs to collaborate using Multi-Agent Reinforcement Learning (MARL). It provides implementations of various MARL algorithms for LLM collaboration and supports different environments and benchmarks.

    About#

    “What are the differences between CoMLRL and other multi-LLM training frameworks?"

    Many works use role-conditioned, parameter-sharing approaches built on single-agent RL training frameworks to implement multi-agent training. Using truly distinct agents better models settings where highly heterogeneous LLMs possess fundamentally different capabilities, and it aligns better with the concept under study — “multi-agent.”

    CoMLRL supports separate actors with decentralized execution, including training with a centralized critic. Its centralized collaboration mode instead uses one actor to generate the complete joint response. The available trainers include REINFORCE, Actor-Critic, and Multi-Agent Preference Learning; each method’s page describes its implemented objective and constraints.

    “Does CoMLRL support single-agent fine-tuning?"

    Yes! The simplest way is to set num_agents=1 in your trainer. However, since we omit fancy optimizations to keep multi-agent training simple, you may not find the single-agent trainers optimal. LLaMA-Factory, trl, OpenRLHF, and verl are good choices for single-agent fine-tuning.

    “Does CoMLRL support self-play/self-improvement/self-evolution with MARL?"

    Yes! Although we focus on LLM collaboration formalized as a Dec-POMDP, users can still customize the interactions with the environment to implement pipelines such as self-play (Spiral) and self-improvement (MAFT). Users can refer to our multi-turn training documentation for more details.

    “Does CoMLRL support distributed training?"

    CoMLRL supports placing whole actor and critic models on multiple devices with parallel_training="mp" in one Python process. It does not provide multi-process data-parallel training or shard an individual model across devices. See Training Parallelization for device configuration.

    “What is LLM collaboration?"

    LLM collaboration refers to problems where LLM agents cooperatively solve tasks in multi-agent systems. The tasks are specified in language and provided to each agent as a prompt, and the agent generates a response synchronously based on its instructions. The set of all agents’ responses jointly forms a solution. Users and systems may validate the solutions to provide additional requirements or suggestions for LLMs. These components form part of the environment for LLM collaboration, with states that may be updated based on the agents’ outputs. The updates are embedded into prompts for subsequent turns. This process iterates until the task is completed or a turn limit is reached.

    “Why should we fine-tune multi-LLM systems with MARL?"

    Many studies have explored LLM-based multi-agent systems for completing tasks with multiple interacting agents. However, most of these models are pretrained separately and are not specifically optimized for coordination, which may limit their performance. In addition, designing effective prompts remains difficult and unclear. Cooperative MARL methods, which optimize a team of agents toward a shared objective, have been extensively studied for years. They naturally fit LLM collaboration and motivate us to bring advances from the well-established MARL community to LLM-based MAS.

    “What are the benefits of decentralized reasoning?"

    In decentralized execution, agents use their own prompts and policies, so independent generations can run concurrently when the device configuration allows it. This supports role-specific models and modular task decomposition. Latency, memory use, and task quality depend on model sizes, prompt lengths, communication, and hardware; decentralization alone does not guarantee a speedup or preserve all information available to a centralized model.

    Features#

    • Cooperative trainers for LLM collaboration:
      • Multi-Agent REINFORCE: Critic-free policy gradient methods, including MAREINFORCE, MAGRPO, MARLOO, and MAREMAX.
        • Joint responses from aligned individual responses with joint_mode='aligned'.
        • Cartesian-product joint responses with joint_mode='cross'.
      • Multi-Agent Actor-Critic: Actor-Critic methods, including IAC and MAAC.
        • Independent actor-critic (separate critic or value head over the LLM backbone).
        • Centralized critic over joint prompts with separate actors.
      • Multi-Agent Preference Learning: MADPO, MARLHF, and their iterative variants.
        • Direct joint preference optimization or a learned joint reward followed by RL.
        • Decentralized actors or one centralized actor with role-aware joint responses.
    • Environments that simulate real-world tasks for training and evaluating LLM collaboration:
      • Writing: Multiple LLM agents collaborate on processing articles.
        • TLDR - Summarizing Reddit posts.
        • ArXiv - Expanding abstracts into introductions.
      • Coding: Generate code solutions for programming problems.
        • MBPP - Mostly basic Python problems.
        • HumanEval - Handwritten evaluation problems.
        • CoopHumanEval - HumanEval with a cooperative nature.
        • ClassEval - Completing class-level code based on attributes and docstrings.
      • Minecraft: Collaborative building tasks in Minecraft.
        • StrBuild - Building structures based on string blueprints.
        • HouseBuild - Constructing houses from given blueprints while defending against spider attacks.
      • Travel: Collaborative travel planning under user constraints.
        • TravelPlanner - Planning multi-day trip itineraries.
      • BFCL v4: Collaborative function calling with tools.
        • Native Parallel - Making parallel function calls.
